\begin{abstract}
Graph Convolutional Networks (GCN) and GraphSAGE represent foundational paradigms in geometric deep learning. While full-batch GCN operates across the global graph topology, it suffers from the neighborhood explosion bottleneck on large graphs. GraphSAGE overcomes this via stochastic neighborhood sampling and mini-batch optimization. In this report, we evaluate both architectures on benchmark datasets: \texttt{ogbn-arxiv} and \texttt{ogbn-products}. We systematically analyze model depth, learning rates, batch sizes, and sampling budgets, presenting empirical profiling of memory scalability and runtime efficiency.
\end{abstract}

\section{Task 1: Full-Batch GCN Reproduction \& Convergence}

\subsection{Experimental Configuration}
Full-batch GCN was trained on the \texttt{ogbn-arxiv} citation network ($|V| = 169,343$, $|E| = 1,166,243$, 40 subject classes). The baseline architecture employs a 3-layer GCN with hidden dimension $d = 256$, batch normalization, dropout $p = 0.5$, and ReLU activations, optimized using Adam ($\eta = 0.01$).

\subsection{Convergence Dynamics}
As visualized in Figure~\ref{fig:gcn_conv}, GCN exhibits rapid, monotonic convergence during the initial 40 epochs, reducing training cross-entropy loss from $4.21$ to $1.05$. Validation accuracy plateaus around epoch 70, reaching a peak validation accuracy of \textbf{71.82\%} and a corresponding test accuracy of \textbf{71.30\%}. This faithfully replicates the official Open Graph Benchmark (OGB) leaderboard baseline ($71.74\% \pm 0.29\%$).

\paragraph{Impact of Model Depth ($L$):} 
Increasing depth from $L=2$ to $L=3$ expands the receptive field, improving test accuracy from $69.66\%$ to $71.30\%$. However, increasing depth further ($L=4, 5, 6$) causes monotonic performance degradation down to $69.72\%$ (Table~\ref{tab:gcn_ablation}). This deterioration is attributed to the \textit{oversmoothing problem}: recursive normalized Laplacian smoothing:
\begin{equation}
H^{(l+1)} = \sigma\left(\tilde{D}^{-\frac{1}{2}}\tilde{A}\tilde{D}^{-\frac{1}{2}} H^{(l)} W^{(l)}\right)
\end{equation}
acts as a low-pass filter on graph signals. As $L \to \infty$, node representations converge to the dominant stationary eigenvector proportional to node degree, collapsing feature distinguishability across classes. Peak memory also grows linearly from 5,445 MB ($L=2$) to 7,788 MB ($L=6$) due to storing full activation maps across all layers.

\paragraph{Impact of Learning Rate ($\eta$):}
A small learning rate ($\eta = 0.001$) converges sluggishly within 80 epochs, underfitting at $67.71\%$ test accuracy. Conversely, an aggressive learning rate ($\eta = 0.05$) induces gradient oscillations and settles into sub-optimal local minima ($68.17\%$). Optimal performance is achieved at $\eta = 0.01$ ($71.30\%$).

\paragraph{Impact of Batch Size ($B$):}
Increasing batch size from 512 to 2048 reduces iteration overhead and improves GPU vector parallelization, dropping per-epoch runtime from $66.29$s to $49.94$s. However, larger batch sizes expand the multi-hop union frontier, driving peak memory up to $9,393.7$ MB. Batch size $B = 1024$ delivers the optimal trade-off between statistical gradient quality and memory ($78.61\%$ test accuracy).

\paragraph{Impact of Layer-wise Neighbor Sample Sizes ($S$):}
Varying the sampling budget reveals a dramatic efficiency-accuracy trade-off (Table~\ref{tab:sage_ablation}). Pruning the fanout from $[15, 10, 5]$ to $[5, 5, 5]$ slashes epoch training time by \textbf{3.6$\times$} ($60.64$s $\to 16.92$s) and cuts peak memory nearly in half ($7,109.7$ MB $\to 3,735.0$ MB), at a modest accuracy cost ($75.92\%$ vs. $78.61\%$). This confirms that smaller sampling budgets are exceptionally effective for fast prototyping and memory-constrained deployments.

Table~\ref{tab:comparative_profile} and Figure~\ref{fig:profiling} contrast the computational profiles. Full-batch GCN computes an entire epoch in only $14.5$ ms on \texttt{ogbn-arxiv} but requires $6.0$ GB of GPU memory for a graph with only 169K nodes.

\subsection{Theoretical Scalability Analysis: The Neighborhood Explosion Bottleneck}
The scalability dichotomy between GCN and GraphSAGE stems from the receptive field structure during backpropagation:

\paragraph{Full-Batch GCN Explosion:}
In full-batch GCN, computing node embeddings at layer $l+1$ requires the global graph adjacency matrix:
\begin{equation}
H^{(l+1)} = \sigma\left(\tilde{A}_{\text{norm}} H^{(l)} W^{(l)}\right)
\end{equation}
To compute exact gradients $\frac{\partial \mathcal{L}}{\partial W^{(l)}}$, automatic differentiation must retain the full activation matrices $\{H^{(0)}, H^{(1)}, \dots, H^{(L)}\}$ in GPU memory simultaneously, requiring $\mathcal{O}(L \cdot |V| \cdot d)$ space, alongside edge storage $\mathcal{O}(|E|)$. For web-scale graphs where $|V| \ge 10^7$ and $|E| \ge 10^9$, full-batch memory overhead becomes impossible.

Furthermore, naive node-wise mini-batching without sampling fails due to \textit{exponential receptive field expansion}. In real-world graphs exhibiting power-law degree distributions with dense hubs, the size of a node's receptive field across $L$ layers expands as:
\begin{equation}
\mathcal{O}\left(d_{\text{avg}}^L\right)
\end{equation}
For a 3-layer model on a graph with average degree $d_{\text{avg}} = 25$, each batch node's receptive field touches $\sim 25^3 \approx 15,625$ nodes; across a batch of $B = 1024$, the union of multi-hop neighborhoods collapses into the entire graph ($|V|$), causing exponential memory blow-up.

\paragraph{Stochastic Sampling Solution (GraphSAGE):}
GraphSAGE circumvents this bottleneck by restricting aggregation to a fixed uniform sample of size $S_l$ at each hop $l \in \{1, \dots, L\}$. For a mini-batch of $B$ target nodes, the maximum computational graph size is strictly bounded by:
\begin{equation}
\text{Sampled Nodes} \le B \cdot \prod_{l=1}^L S_l
\end{equation}
This caps per-batch memory to $\mathcal{O}\left(B \cdot d \cdot \prod_{l=1}^L S_l\right)$, which is \textbf{strictly independent of total graph size $|V|$ and $|E|$}. Consequently, stochastic neighborhood sampling decouples training memory from graph scale, enabling scalable representation learning on graphs of arbitrary magnitude.

\section{Conclusion}
This study reproduced node classification for GCN and GraphSAGE on OGB benchmarks, verifying that depth $L=3$ and learning rate $\eta=0.01$ optimize GCN, while batch size $B=1024$ and fanout $[15,10,5]$ optimize GraphSAGE. Profiling confirmed that stochastic neighborhood sampling effectively prevents the neighborhood explosion, providing bounded memory scalability on massive graph structures.
